# POR QUE ISTO EXISTE: as docs do corpus citam trecho de codigo do core o tempo
# todo, e toda edicao minha no core FAZ AS LINHAS ANDAREM. Ancorar em NUMERO DE
# LINHA e' fragil: um bump de schema desloca dezenas de citacoes de uma vez, EM
# SILENCIO (o `ast-17`/`ast-18` mexeu +6/+34; a esteira de reconciliar numero era
# paga a mao). A ancora aqui e' o NOME DA FUNCAO -- ele so' muda quando alguem
# renomeia a funcao de verdade (evento semantico, raro e visivel). *(Regra do
# Diego, 2026-07-23: "citar as linhas e' fragil; use os nomes das funcoes".)*
#
# Formato:  <arquivo relativo ao core> <TAB> <funcao> <TAB> <trecho que TEM de
#           estar DENTRO do corpo dela>. Funcao `-` = arquivo sem funcao (header,
#           .ch de diretiva): o trecho e' procurado no arquivo inteiro.
#
# A guarda (corpus_refs em ppcorpus.sh) extrai o corpo da funcao (da assinatura em
# coluna 0 ate' o `}` em coluna 0) e confere que o trecho esta' la'. Falha alta se
# a funcao sumiu/foi renomeada ou o trecho mudou -- nunca por deslocamento de linha.
